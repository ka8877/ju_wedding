# 조현범 · 권주영의 모바일 청첩장

주영님이 직접 사진·예식 정보·계좌·디자인을 바꾸는 모바일 청첩장입니다. 개인 GitHub 아이디가 없는 무료 Cloudflare Pages 주소를 사용하고, Supabase 무료 요금제로 사진과 공개 내용을 저장합니다. 유료 도메인은 사용하지 않습니다.

- **청첩장:** https://hyunbeom-juyoung.pages.dev/
- **관리 페이지:** https://hyunbeom-juyoung.pages.dev/#/admin
- **개발자용 초기 연결 안내:** [SETUP.md](docs/SETUP.md)
- **보조 주소:** https://ka8877.github.io/ju_wedding/

운영 저장소와 관리자 권한은 준비되어 있습니다. 사용자는 관리 페이지에 로그인해 청첩장 내용만 편집합니다. 지도·공유·저장소 연결은 개발자가 관리하며 편집 화면에서 키나 SQL을 입력하지 않습니다.

## 두 개의 화면

- **청첩장:** 사이트의 기본 주소. 공개한 내용만 하객에게 표시합니다.
- **관리 페이지:** 기본 주소 뒤에 `#/admin`. 사진, 기본 정보, 예식 장소, 계좌, 디자인을 편집하고 미리 본 뒤 공개합니다.

예식은 **2027년 2월 20일 토요일 낮 12시 30분 · HD현대글로벌R&D센터 아산홀**로 기본 설정했습니다. 부모님 성함과 장남·차녀 소개도 반영했습니다. 사진·계좌·교통과 대절버스 세부 내용은 관리 화면에서 채웁니다. 예전 저장 내용의 빈 정보만 한 번 채우며, 이후 직접 비운 값은 그대로 유지합니다.

## 주영님이 고르는 추가 기능

- **음악:** 버튼을 눌러 듣는 산뜻한 기본 연주, 음량·표시 여부
- **사진:** 2장·3장 행이 번갈아 나오는 콜라주, 처음 3줄 뒤 펼쳐보기, 다른 배치와 접힘 줄 수 선택
- **참석 응답:** 신랑·신부별 안내, 참석·식사·대절버스 의사, 전달한 내용 확인, 관리자 목록과 Excel용 CSV
- **현장 스냅:** 2027년 2월 20일부터 열리는 비공개 사진 접수와 관리자 확인
- **교통·버스:** 지하철·버스·자가용·주차 안내, 대전·경주 대절버스 펼침 안내
- **카카오 공유:** 카카오톡 전용 기본 공유 버튼, 링크 복사와 QR

관리 화면의 **추가 기능**에서 문구·음악·접수 여부·오픈 날짜를 바꾸고 **하객 응답**에서 접수 내역을 봅니다. 현재 운영 사이트의 저장소 연결은 완료됐으며 현장 사진은 예식일부터 받습니다. 새 프로젝트를 만드는 개발자는 [저장소 설정](docs/SETUP.md#참석-응답과-현장-사진-저장소-추가)을 참고하세요. 실제 저장되지 않은 내용을 전달 완료로 표시하지 않습니다.

## 두 분이 직접 고르는 디자인

- **6가지 레이아웃:** 보태니컬 가든, 에디토리얼, 시네마틱 러브, 타임리스 클래식, 그레이스 채플, 디어 마이 러브
- **처음에는 추천 조합 4개** 중 하나를 고르고, **랜덤 추천**으로 잘 어울리는 12개 조합을 둘러볼 수 있습니다.
- **9가지 색감**, 직접 고르는 포인트 색상, **5가지 글꼴·6가지 배경**과 글자 크기
- 첫 화면 제목·사진 모양·사진 위치·갤러리 배치·장식 표시
- 섹션 순서·표시 여부·제목, 초대 문구 추천과 직접 작성
- 성경 말씀 추천·내용 수정, 직접 쓰는 축복 기도
- 실행 취소·다시 실행, 전체 청첩장 백업·가져오기

템플릿을 바꿔도 두 분의 사진·이름·장소·계좌와 직접 쓴 문구는 유지됩니다. 기존 버전에서 저장한 초안도 새 디자인 기본값을 채워 불러옵니다.

추천·랜덤 조합은 글귀·기본 정보·사진·말씀·기도·섹션 순서를 바꾸지 않고 꾸밈만 적용합니다. 세부 설정은 **직접 세부 꾸미기**를 열었을 때만 보이므로, 추천 하나만 골라도 사용할 수 있습니다. 스타일 선택은 자동 저장·공개되지 않으며 미리보기로 확인하고 반영합니다.

사용자 편집 화면에는 연결 안내·API 키·좌표 입력을 표시하지 않습니다. 하객은 날짜와 시간이 정해진 예식을 **캘린더에 저장**할 수 있습니다. 한국 시간을 정확히 변환한 일정 파일을 만들며, 미정 시간이나 예식 길이는 임의로 넣지 않습니다.

## 링크와 QR로 청첩장 전하기

관리 화면의 **소중한 분께 전해요**에서 링크를 복사하거나 **QR 코드 보기**를 누르세요. 하객 화면 맨 아래에서도 공유와 QR을 사용할 수 있습니다. QR은 기기 안에서 생성하며 외부 QR 서비스로 청첩장 주소를 보내지 않습니다. **QR 이미지 저장**은 인쇄·메시지 첨부용 1024px PNG를 저장합니다.

QR과 공유 링크는 관리·연결 안내 경로와 추적 정보를 제외한 공개 청첩장으로 연결됩니다. Cloudflare 사이트에서 저장한 QR은 새 주소로 연결되고, 이전에 저장하거나 인쇄한 GitHub Pages QR은 보조 사이트로 계속 연결됩니다. 사진과 문구를 바꿔도 공개 주소가 같으면 QR을 다시 만들 필요가 없습니다. 이 기기에만 저장한 초안은 공유 링크로 전달하지 않습니다.

현재 Cloudflare Pages 빌드의 `VITE_PUBLIC_SITE_URL`은 `https://hyunbeom-juyoung.pages.dev/`입니다. 공유 미리보기와 로컬 QR 기본 주소가 이 설정을 사용합니다. 로컬 개발·미리보기에서 이 변수를 생략하면 코드의 기본값인 기존 GitHub Pages 주소를 사용합니다. [현재 무료 호스팅 설정](docs/SETUP.md#현재-cloudflare-pages-배포-설정)을 참고하세요.

## 개발

Node.js 24 LTS를 사용합니다.

```bash
cd /workspace/ju_wedding
npm ci
npm run dev
```

```bash
npm test
npm run test:db
npm run build
npm run test:e2e
npm run test:e2e:guest
```

`test:db`는 메모리에서 실행되는 실제 PostgreSQL(PGlite)로 기본 청첩장과 하객 접수 SQL·RLS 정책을 검사합니다. 익명 개인정보 조회 차단·관리자 권한·초안 분리·응답 검증·예식일 사진 접수·예약 경로·마이그레이션 재실행을 확인합니다. 실제 Supabase Auth, Storage API 파일 검사와 CDN·서명 URL 전송은 연결 후 별도로 검증합니다. `test:e2e:guest`는 클라우드 모드에서 HTTP 응답을 모의 처리해 접수 화면과 관리자 CSV를 확인하며, 실제 프로젝트에 하객 정보를 전송하지 않습니다.

이 프로젝트의 기존 체크아웃을 사용하세요. 클라우드 작업은 이미 격리돼 있으므로 별도 Git worktree는 필요하지 않습니다.

## 실제 공개 사이트로 연결하기

**[초기 연결 안내](docs/SETUP.md)**에 준비된 무료 Supabase 프로젝트의 SQL 실행, 주영님 계정 등록, 읽기 전용 연결 점검을 정리했습니다. 공개 연결값이 코드에 있어 GitHub 변수를 따로 등록하지 않아도 됩니다. `main` 코드 변경은 자동 배포되고, 주영님의 사진·문구 변경은 관리 페이지에서 공개하므로 GitHub를 열 필요가 없습니다.

`npm run check:connection`은 기본 공개 설정(또는 환경 변수·`.env.local` 덮어쓰기)으로 실제 공개 조회와 익명 접근 제한, 사진 버킷 경로를 읽기 전용으로 확인합니다. 관리자 로그인과 실제 업로드 검사는 별도로 필요합니다. secret/service-role 키는 사용하지 않습니다.

로컬 미리보기 모드의 수정은 다른 기기나 하객의 청첩장에 전달되지 않습니다. 실제 사진 저장과 공개 내용 변경은 준비된 Supabase 프로젝트를 사용합니다.

연결 후에는 관리자가 **임시 저장 → 미리보기 → 공개** 순서로 작업합니다. 디자인 코드 변경은 `main`에 반영할 때 Cloudflare Pages가 검사·빌드 후 자동 배포하고, GitHub Actions도 보조 사이트를 검사 후 다시 배포합니다. 사진과 문구 변경은 관리 페이지에서 처리하므로 코드 배포가 필요 없습니다.

예식 날짜·시간·장소가 아직 미정이어도 디자인과 문구를 먼저 공개할 수 있습니다. 빈 정보는 준비 중으로 표시합니다. 공개 버튼은 서버 저장 뒤 익명 방문자와 같은 경로로 내용을 다시 읽어 일치해야 성공을 알리며, 오류와 결과는 항상 하단 버튼 옆에 표시합니다.

관리자는 여러 명 등록할 수 있습니다. Supabase에서 각 이메일의 계정을 만들고 최초 연결 안내의 관리자 권한 등록을 반복하세요. 기존 관리자는 유지되며 모두 같은 청첩장을 공동 편집합니다. 동시에 저장하면 나중 저장 내용이 적용됩니다.

## 공개 범위

- 청첩장에 공개한 문구·사진·계좌번호는 링크를 아는 사람이 읽을 수 있습니다.
- 사진은 공개 저장 버킷을 사용합니다. **업로드한 파일은 최종 공개 전에도 파일 주소를 아는 사람이 볼 수 있으므로**, 공개해도 되는 사진만 올리세요.
- 관리자 계정은 Supabase Auth로 인증하고 데이터베이스·사진 쓰기 권한은 관리자 목록으로 제한합니다. 회원가입만으로 관리 권한이 생기지 않습니다.
- 프런트엔드에는 공개용 키만 사용합니다. `service_role` / secret 키와 관리자 비밀번호는 GitHub 저장소나 클라이언트 코드에 넣지 않습니다.
- 사진은 JPG, PNG, WebP, AVIF, 파일당 최대 8 MiB입니다. 휴대폰의 HEIC 사진은 JPG로 변환해서 올리세요.
- 참석 응답과 현장 스냅은 별도의 비공개 저장소를 사용합니다. 응답·연락처와 사진은 관리자만 확인하며, 현장 사진은 한 번에 5장까지 선택하고 압축 후 장당 2 MiB 이하로 저장합니다.

네이버 지도와 카카오톡 전용 공유를 기본으로 연결하는 코드를 준비했습니다. 실제 앱 등록과 공개 키 연결을 마친 뒤 배포해야 하며, 현재 운영 사이트는 이전 연결 방식입니다. 사용자는 장소 이름과 주소를 입력하거나 검색 결과를 선택하면 됩니다. 지도·카카오 연결값은 `src/lib/integrations.ts` 또는 배포 환경 변수에서 개발자가 관리합니다. [개발자용 지도·공유 연결 안내](docs/SETUP.md#지도와-카카오톡-공유-개발자-설정)를 참고하세요.

## 무료 주소

별도 도메인 구매 없이 `hyunbeom-juyoung.pages.dev`를 사용합니다. Cloudflare Pages의 Git 연동으로 `main` 변경이 자동 배포됩니다. 기존 `ka8877.github.io/ju_wedding/` 주소도 보조 사이트로 유지하며, GitHub Actions의 배포 요약은 이 보조 주소를 안내합니다.
