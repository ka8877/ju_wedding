# 개발자용 운영·연결 안내

- 청첩장: **https://hyunbeom-juyoung.pages.dev/**
- 관리 페이지: **https://hyunbeom-juyoung.pages.dev/#/admin**
- 개발자용 초기 연결 화면: **https://hyunbeom-juyoung.pages.dev/#/setup**

유료 도메인은 사용하지 않으며 **Cloudflare Pages 운영 주소 하나만** 사용합니다. 코드가 `main`에 반영되면 Cloudflare Pages의 Git 연동으로 검사·빌드 후 자동 배포됩니다. GitHub 저장소와 Actions는 소스 코드와 자동 검사를 관리하며 GitHub Pages 자동 배포는 사용하지 않습니다. Supabase를 연결하면 주영님은 관리 페이지에서 사진·문구·장소·계좌를 변경하고 **공개**만 누르면 됩니다. 그때마다 GitHub를 열거나 코드를 배포할 필요가 없습니다.

이 문서는 개발자·운영 담당자를 위한 안내입니다. 일반 사용자 화면에서는 초기 연결 화면, API 키, 도메인 등록, 좌표 입력을 안내하지 않습니다. 사용자는 관리 페이지에서 이름·예식 장소·사진·문구만 편집하고 공개합니다.

현재 프로젝트의 공개 연결값은 `src/lib/public-config.ts`에 등록돼 있습니다. 공개 키는 관리자 권한을 주지 않습니다. **프로젝트의 SQL·관리자 계정이 준비되고 실제 연결 검증을 마쳐야** 다른 휴대폰에 저장한 내용을 전달할 수 있습니다. Supabase 무료 요금제로 시작하며, 서비스의 사용량·용량 제한과 프로젝트 활성 상태는 확인해야 합니다.

## 처음 한 번 필요한 것

### 1. 준비된 프로젝트

프로젝트 **fasdkmqdgukptnuvofwp**를 사용합니다. 공개 Project URL과 publishable key가 이미 코드에 등록돼 있어 GitHub 변수를 직접 등록할 필요가 없습니다. `secret`·`service_role` 키, 계정 비밀번호, 데이터베이스 비밀번호는 전달하지 않습니다.

### 2. 저장소와 주영님 계정 준비

1. [이 프로젝트의 SQL Editor](https://supabase.com/dashboard/project/fasdkmqdgukptnuvofwp/sql/new)에서 [001_wedding.sql](../supabase/migrations/001_wedding.sql), [002_guest_features.sql](../supabase/migrations/002_guest_features.sql)을 순서대로 실행합니다. 사이트 연결 안내의 **초기 설정 SQL 복사**는 둘을 함께 복사합니다. 재실행해도 기존 청첩장과 관리자 등록은 유지됩니다.
2. [이 프로젝트의 사용자 관리](https://supabase.com/dashboard/project/fasdkmqdgukptnuvofwp/auth/users)에서 **Add user → Create new user**를 선택하고 주영님이 사용할 이메일과 비밀번호로 사용자를 만듭니다. **Auto Confirm User**를 켭니다. 비밀번호는 채팅이나 저장소에 적지 않습니다.
3. SQL Editor에서 실제 이메일을 넣어 관리자 자격을 등록합니다.

```sql
insert into public.wedding_admins (user_id)
select id from auth.users
where lower(email) = lower('여기에-주영님-이메일')
on conflict (user_id) do nothing;
```

4. **Authentication → Sign In / Providers → Email**에서 이메일 로그인은 사용하고 공개 회원가입은 끕니다. 이 앱은 관리자 전용이며 회원가입만으로 관리 권한을 주지 않습니다.
5. **Authentication → URL Configuration → Site URL**은 운영 주소인 `https://hyunbeom-juyoung.pages.dev/`로 맞춥니다. 현재 이메일·비밀번호 로그인은 리디렉션을 사용하지 않습니다. 운영 주소에서 기존 관리자 계정으로 로그인합니다.

이 작업은 Supabase 프로젝트 소유자 권한이 필요합니다. 공개 키만으로 계정 생성·SQL 실행을 대신할 수는 없습니다.

### 3. 연결 확인과 자동 배포

연결 담당자가 다음 명령을 실행합니다. 기본으로 코드에 등록된 **공개 연결값**을 사용하며, 선택적으로 환경 변수 또는 `.env.local`의 URL·공개 키를 함께 설정해 덮어쓸 수 있습니다. 키 값과 서버 오류의 원문을 로그로 출력하지 않습니다.

```bash
npm run check:connection
```

점검은 다음을 **읽기 전용**으로 확인합니다.

- 공개 청첩장 조회 함수와 응답 형식. 아직 공개한 내용이 없어도 정상입니다.
- 익명 사용자가 관리자 목록과 초안 테이블을 직접 읽지 못하는지.
- 공개 사진 버킷 경로가 준비됐는지. 사진을 올리거나 삭제하지 않습니다.

현재 클라우드 환경에서 프로젝트의 `fasdkmqdgukptnuvofwp.supabase.co` 주소가 차단됐다면 먼저 환경의 네트워크 허용 설정이 적용돼야 합니다. 연결 점검을 실제로 통과하기 전에는 사진 저장이나 관리자 로그인이 검증됐다고 안내하지 않습니다.

코드를 `main`에 반영하면 Cloudflare Pages가 아래의 현재 빌드 설정으로 검사·배포합니다. GitHub Actions는 단위 테스트·데이터베이스 정책·모바일 화면·프로덕션 빌드를 검사하고 Supabase의 공개 데이터 연결을 진단합니다. 사이트 배포는 Cloudflare Pages에서만 수행합니다. Supabase 연결 점검은 별도 진단이며, 통과하지 않은 상태에서 사진 저장·관리자 로그인이 준비됐다고 안내하지 않습니다. 사용자에게 GitHub 변수 등록이나 배포 버튼 클릭을 반복 요청하지 않습니다.

## 주영님이 사용하는 순서

1. [관리 페이지](https://hyunbeom-juyoung.pages.dev/#/admin)에 이메일·비밀번호로 로그인합니다.
2. 사진과 기본 정보를 입력한 뒤, 디자인 탭에서 **추천 조합** 하나를 고르거나 **랜덤 스타일 추천**을 눌러 보세요. 마음에 드는 조합이면 세부 옵션을 고를 필요가 없습니다. 더 바꾸고 싶을 때만 **직접 세부 꾸미기**를 여세요.
3. **초안 저장** 후 미리보기로 확인하고 **공개**합니다.
4. 다른 휴대폰이나 시크릿 창에서 [청첩장](https://hyunbeom-juyoung.pages.dev/)을 열어 확인합니다.

사진·문구 변경에는 GitHub 작업이 필요 없습니다. 디자인 코드 변경만 `main` 반영 → 자동 검사 → 자동 배포 순서로 진행됩니다.

## QR과 링크로 전하기

관리 화면의 **소중한 분께 전해요**에서 링크를 복사하거나 **QR 코드 보기 → QR 이미지 저장**으로 1536px 하트 패턴 PNG를 내려받을 수 있습니다. 하객용 청첩장 하단에서도 QR과 공유 버튼을 사용할 수 있습니다. QR 기준점을 왼쪽·오른쪽·아래에 배치하고 QR 패턴 전체를 하트 실루엣으로 그립니다. 외부 생성 서비스 없이 기기에서 만들며, 저장한 이미지 전체를 사용해 스캔 기준점과 여백을 유지하세요.

QR과 공유 링크의 운영 주소는 `https://hyunbeom-juyoung.pages.dev/`입니다. 로컬 미리보기는 `VITE_PUBLIC_SITE_URL`을 사용하고, 변수를 생략해도 코드의 기본값인 같은 Cloudflare 주소를 사용합니다. 관리자 주소·로그인 정보·저장하지 않은 초안은 QR에 포함되지 않습니다. 이전 GitHub Pages 주소를 담은 QR은 현재 운영 주소용으로 다시 생성해 교체하세요. 공유하기 전에 **공개 청첩장에 반영**하고 다른 휴대폰에서 확인해 주세요.

메시지에 링크를 붙였을 때 표시되는 미리보기 이미지는 이름을 담은 기본 이미지입니다. 관리자 화면에서 고른 사진·디자인에 따라 자동 변경되지는 않습니다.

## 지도와 카카오톡 공유 개발자 설정

지도·공유 연결은 청첩장 콘텐츠와 분리해 개발자가 한 번 설정합니다. `src/lib/integrations.ts`의 `publicIntegrationConfig`에 **공개용** 식별자를 등록하거나, Cloudflare Pages의 빌드 환경 변수 `VITE_NAVER_MAP_CLIENT_ID`, `VITE_KAKAO_JAVASCRIPT_KEY`를 설정하고 배포합니다. 환경 변수 → 코드의 서비스 설정 → 예전 문서에 저장된 공개값 순서로 유효한 값을 사용합니다. 네이버의 코드 기본값은 운영 빌드에서만 사용하며, 개발 서버에서는 명시적인 환경 변수나 테스트용 저장값만 사용해 운영 한도를 소모하지 않습니다. Client Secret, REST API secret, 계정 비밀번호는 프런트엔드에 넣지 않습니다. 사용자는 이 값을 입력하거나 수정하지 않습니다.

네이버 지도는 [네이버 클라우드 Maps 애플리케이션](https://guide.ncloud-docs.com/docs/application-maps-app-vpc)을 다음과 같이 등록합니다.

- **Application 이름:** `hbjy-wedding` — 영문자로 시작하는 이름을 사용합니다.
- **선택 API:** Dynamic Map, Geocoding
- **Web 서비스 URL:** `https://hyunbeom-juyoung.pages.dev` 하나만 등록
- **공개용 Client ID:** `naverMapClientId` 또는 `VITE_NAVER_MAP_CLIENT_ID`에 등록

운영 앱은 소유자가 대표 계정임을 확인하고 다음 사용 한도를 저장했습니다. 두 API 모두 **한도 초과 사용 → 허용안함**을 사용합니다.

| API | 일별 한도 | 월별 한도 |
| --- | ---: | ---: |
| Dynamic Map | 1,000 | 10,000 |
| Geocoding | 100 | 1,000 |

무료량은 대표 계정의 모든 앱 사용량을 합산해 적용합니다. 다른 앱을 추가하거나 대표 계정을 변경할 때는 무료 적용과 한도를 다시 확인합니다. 이 설정은 Maps API의 사용 한도이며 계정 전체의 결제를 차단하는 기능은 아닙니다. [공식 무료 이용 안내](https://www.ncloud.com/support/faq/all/2828)

본문에는 네이버 지도만 표시하며, Google·카카오는 보조 메뉴에서 새 탭으로 엽니다. 키 미설정·인증·네트워크 오류 시에는 작은 안내와 네이버 외부 링크만 표시하며, 다른 지도로 자동 대체하지 않습니다. 실제 키와 운영 도메인의 인증을 확인해야 본문 지도 활성화가 완료됩니다. HD현대글로벌R&D센터의 확인된 좌표는 위도 `37.3768838`, 경도 `127.1043929`입니다. 기존 문서의 좌표가 비어 있어도 같은 장소와 주소라면 이 위치를 사용합니다.

카카오톡 직접 공유는 Kakao Developers 앱의 **JavaScript SDK 도메인**과 **제품 링크 관리 → 웹 도메인**에 `https://hyunbeom-juyoung.pages.dev`를 등록하고 기본 제품 링크도 같은 운영 주소로 설정합니다. **JavaScript 키**는 `kakaoJavascriptKey` 또는 `VITE_KAKAO_JAVASCRIPT_KEY`에 등록합니다. 하객 화면에는 공유와 하트 QR 두 동작을 표시합니다. 카카오 키가 연결되면 기본 공유 버튼이 카카오톡으로 전환되며, 키가 없으면 기기의 기본 공유창을 사용합니다. 기기 공유를 지원하지 않으면 링크를 복사합니다. 복사만 한 상태를 전송 완료로 표시하지 않습니다.

## 참석 응답과 현장 사진 저장소 추가

이미 기본 청첩장을 사용 중이라면 [연결 안내](https://hyunbeom-juyoung.pages.dev/#/setup)의 **05 참석 응답 · 현장 사진 연결하기**에서 추가 설정 SQL을 복사해 Supabase SQL Editor에서 실행합니다. 이 작업은 프로젝트 소유자 권한이 필요합니다. 공개 키로는 테이블과 권한을 생성할 수 없어, 코드 배포만으로 실제 접수가 활성화되지는 않습니다.

**추가 기능 연결 확인**으로 저장 공간을 확인한 뒤, 관리 화면의 **추가 기능**에서 접수·오픈 날짜·신랑측/신부측 안내를 확인하고 공개합니다. 응답은 **하객 응답** 메뉴에서 필터링하고 Excel에서 열 수 있는 UTF-8 CSV로 내려받습니다. 연락처는 선택 사항이며, 응답은 관리자만 조회합니다. 전송 실패 시 완료 화면을 보여주지 않고 다시 시도할 수 있습니다.

현장 사진은 기본으로 **2027-02-20 한국 시간 0시**부터 접수하며 서버에서도 날짜와 공개한 사용 여부를 검사합니다. 사진은 공개 갤러리와 분리된 비공개 버킷에 저장하고, 관리자 화면에서 한 시간 동안 유효한 링크로 확인합니다. JPG·PNG·WebP·AVIF를 한 번에 최대 5장 선택할 수 있고, 원본 8 MiB 이하·변환 후 장당 2 MiB 이하를 지원합니다. 한 탭에서 시간당 5장, 전체 최대 500개 예약 한도가 있으며 실패한 미업로드 예약은 만료 후 정리됩니다.

관리 화면에서 음악은 기본 연주 5곡의 선택·미리 듣기·켜기·끄기·음량을 조정합니다. 예전에 등록한 음악 주소는 재생 호환을 위해 유지하며 편집 화면에 표시하지 않습니다. 초대 문구·사진·교통·대절버스 정보는 직접 입력합니다. 계좌는 신랑측/신부측 펼침 항목으로 표시됩니다. 지도와 카카오톡 공유의 서비스 연결은 개발자가 관리합니다. 편집 사용자는 키·도메인·SQL을 다루지 않습니다.

하객 화면에서는 사진이 없는 갤러리와 내용이 없는 대절버스 안내를 숨깁니다. 관리 미리보기에서는 해당 항목을 편집할 수 있도록 빈 상태를 유지합니다. 지도는 예식장과 가까운 역을 한 화면에 표시하며 확대·축소는 네이버 기본 조작을 사용합니다.

## 현재 Cloudflare Pages 배포 설정

현재 운영 프로젝트는 **hyunbeom-juyoung**이며, 무료 주소 **https://hyunbeom-juyoung.pages.dev/**에서 배포를 확인했습니다. 기존 Supabase 프로젝트와 공개한 청첩장 데이터는 그대로 사용합니다.

| 항목 | 설정값 |
|---|---|
| GitHub 저장소 | `ka8877/ju_wedding` |
| 운영 브랜치 | `main` |
| 빌드 명령(권장) | `npm test && npm run test:db && npm run build` |
| 출력 폴더 | `dist` |
| 루트 폴더 | 저장소 루트(빈칸 기본값) |
| `NODE_VERSION` | `24` |
| `BASE_PATH` | `/` |
| `VITE_PUBLIC_SITE_URL` | `https://hyunbeom-juyoung.pages.dev/` |

Cloudflare GitHub 앱은 이 저장소에만 연결돼 있습니다. `main` 수정은 Cloudflare Pages에서 검사·빌드 후 자동 배포됩니다. 기존 Supabase 공개 설정을 사용하므로 새 비밀 키는 필요하지 않으며, 운영 빌드에 `VITE_LOCAL_PREVIEW=true`를 설정하지 않습니다.

공유 미리보기의 canonical·OG 주소와 로컬 QR 기본 주소는 `VITE_PUBLIC_SITE_URL`을 사용합니다. 코드 자체의 기본값도 `https://hyunbeom-juyoung.pages.dev/`이며, 미리보기에서 만드는 공유 링크 역시 운영 주소를 사용합니다.

공개 내용과 관리자 로그인 화면, QR 버튼, 공유 메타데이터는 운영 주소에서 확인합니다. 실제 관리자 로그인·사진 업로드는 별도 확인 대상입니다. 사진·문구는 계속 관리 화면에서 공개하며, 배포 결과는 Cloudflare Pages의 배포 상태와 운영 주소에서 확인합니다. GitHub Actions에는 사이트 배포 단계가 없습니다.

기존에 게시된 GitHub Pages 사이트는 자동 배포 제거와 별개로 저장소 소유자가 **Settings → Pages → Unpublish site**에서 비공개 처리해야 합니다. [기존 사이트 설정](https://github.com/ka8877/ju_wedding/settings/pages)에서 실제 게시 해제 상태를 확인합니다. 저장소와 Cloudflare의 Git 연동은 유지합니다.

설정 참고: [Cloudflare Git 연동 안내](https://developers.cloudflare.com/pages/get-started/git-integration/).

## 실제 연결 후 확인할 것

`npm run check:connection`은 관리자 비밀번호를 받지 않는 읽기 전용 검사입니다. 다음 동작은 실제 관리자 계정으로 별도 확인합니다.

- 비로그인 상태에서 관리 페이지에 로그인이 필요한지.
- 연결 안내의 **연결 확인**에서 공개 데이터 형식·초안과 관리자 목록 보호·사진 저장 공간이 모두 확인되는지. 이 검사는 로그인하거나 사진을 업로드하지 않습니다.
- 초안 저장만 한 수정은 다른 기기에 보이지 않고 **공개** 후 보이는지.
- 사진이 다른 휴대폰에서도 열리고, 장소 지도·길찾기·주소 복사가 작동하는지.
- 관리자 목록에 없는 로그인 사용자가 초안·사진을 수정하지 못하는지.

`npm run test:db`는 실제 PostgreSQL(PGlite)에서 기본 청첩장과 하객 접수 SQL·RLS 정책을 검사합니다. 인증·저장소 스키마만 모의 구성하므로 호스팅된 Supabase Auth, Storage API의 실제 파일 제한과 CDN 검증을 대신하지 않습니다. 모바일 테스트는 로컬 편집 또는 별도 클라우드 모드의 모의 HTTP 응답을 사용하며 실제 계정 로그인·하객 접수 검사는 아닙니다.

## 사진과 계좌 공개 범위

공개한 청첩장과 계좌는 링크를 아는 사람이 볼 수 있습니다. 사진은 공개 버킷을 사용하므로 업로드한 파일은 최종 공개 전에도 파일 URL을 아는 사람이 볼 수 있습니다. 공개해도 되는 사진만 올리세요.

JPG·PNG·WebP·AVIF, 파일당 8 MiB 이하를 지원합니다. iPhone HEIC는 JPG로 변환해야 합니다. 관리 화면에서 사진을 빼더라도 기존 파일 URL은 유효할 수 있습니다. 완전 삭제는 다른 항목에서 사용하지 않는 파일임을 확인한 뒤 Supabase **Storage → wedding-photos**에서 수행합니다.

## 개발자용 실행

기존 체크아웃을 그대로 사용합니다. 이미 격리된 클라우드 작업이므로 별도 worktree는 필요하지 않습니다. Node.js 24 LTS 기준입니다.

```bash
npm ci
npm run dev
```

개발 서버도 기본으로 코드의 공개 연결값을 사용합니다. 다른 프로젝트로 바꿀 때만 `.env.example`을 `.env.local`로 복사해 URL과 공개 키를 함께 입력하고 개발 서버를 다시 시작합니다. `.env.local`은 Git에 포함되지 않습니다.

```bash
npm test
npm run test:db
npm run build
npm run test:e2e
npm run test:e2e:guest
npm run check:connection
```

마지막 명령은 실제 Supabase의 읽기 전용 연결 점검입니다. 연결 불가나 SQL 미준비 상태는 실패로 정확히 보고합니다. 모바일 자동 테스트는 별도 로컬 미리보기 모드로 실행하므로 호스팅된 로그인·사진 저장 검증과 구분합니다.

## 문제 해결

- **로그인되지만 저장 실패:** 로그인 사용자 UUID가 `wedding_admins`에 등록됐는지 확인합니다. RLS를 끄지 않습니다.
- **로그인 실패:** 이메일·비밀번호, 사용자 확인 상태, 프로젝트 활성 상태를 확인합니다.
- **사진 실패:** 파일 형식·8 MiB 제한·사진 버킷·사용량을 확인합니다.
- **다른 기기에 수정 없음:** 미리보기 모드가 아닌지 확인하고 초안 저장 다음에 **공개**했는지 확인합니다. 공개 설정을 바꾼 뒤에는 배포가 한 번 필요합니다.
- **장소 검색 없음:** 검색 서비스의 사용량·데이터 범위 차이일 수 있습니다. 정확한 주소와 위치를 직접 지정할 수 있습니다.
- **운영 코드가 갱신되지 않음:** Cloudflare Pages 프로젝트 `hyunbeom-juyoung`의 연결 저장소·운영 브랜치 `main`·빌드 상태를 확인합니다. GitHub Actions 검사 성공과 Cloudflare 운영 배포 완료는 각각 확인합니다.


## 전체 글꼴과 세부 꾸미기

**디자인 → 직접 세부 꾸미기 → 글자와 첫 화면**에서 고른 글꼴은 제목·이름·영문·날짜·본문·버튼과 BGM, 입장 이름, QR·참석 응답·현장 사진 안내창까지 함께 적용합니다. 6가지 글꼴 모두 같은 범위에 적용합니다. 기존 다정한 손글씨와 새 또박또박 손글씨(Gaegu)를 선택할 수 있으며, 지도·공유·응답 버튼과 동의·안내 문구는 별도 최소 크기·굵기·명암을 보정합니다. 글자 크기를 작게 골라도 기능 문구가 읽기 어려울 만큼 줄어들지 않도록 했습니다. 지도 서비스가 그리는 기본 조작·저작권 표시는 지도 서비스의 글꼴을 유지합니다.

**간격과 모양**에서 줄 간격, 글자 간격, 본문 정렬, 구역 사이 여백, 버튼 모양, 사진 사이 간격을 바꿀 수 있습니다. **간격과 모양만 기본으로**는 이 여섯 항목만 되돌립니다. 다른 글꼴·색감·사진·입력한 문장은 유지하며 실행 취소로 이전 선택으로 돌아갈 수 있습니다. 추천 스타일이나 템플릿을 바꿔도 세부 간격 선택은 유지합니다.

기존 저장 내용과 백업에는 새 항목의 기본값을 보완해서 읽습니다. 코드를 배포하는 과정에서 초안이나 공개 내용을 다시 저장하지 않습니다. 새 선택은 기존의 초안 저장·미리보기·공개 반영 흐름으로 저장합니다.

참석 응답에서는 실제 안내가 등록된 대절버스 노선만 신청할 수 있습니다. 안내가 모두 비어 있으면 버스 질문을 숨기며, 작성 중 없어진 노선은 새 응답에 포함하지 않습니다. 이미 접수된 응답은 변경하지 않습니다.

## 입장 효과와 미리보기

관리 화면의 **추가 기능 → 문 열림 효과 미리보기**에서 실제 정원 입장 영상을 반복 확인할 수 있습니다. 리본 표지가 열리고 꽃과 철제 대문을 지나 정원의 신랑신부에게 다가가는 약 10.2초 영상이며, 마지막 장면에 두 분의 이름을 표시한 뒤 본문으로 전환합니다. 기존 CSS 종이문·봉인 효과는 제거했습니다.

영상과 포스터는 `public/garden-entrance.mp4`, `public/garden-entrance-poster.jpg`에서 자체 제공합니다. 참고한 모션 원본은 `https://cdn-letterbmotion.barunsoncard.com/tpl_584a6f4c-3be7-4b3c-9bfd-72f5096a8327/intro-4.mp4`입니다. 하객의 사진·이름·문구는 영상 파일에 넣지 않고 기존 청첩장 데이터를 그대로 사용합니다.

하객 화면에는 **건너뛰기**를 표시하며 Escape로도 즉시 진입할 수 있습니다. 일반 주소로 새로 접속하거나 새로고침할 때마다 입장을 다시 재생하며, 예전 `v6` 방문 기록은 재생을 생략하지 않습니다. 같은 페이지에서 콘텐츠가 갱신되는 동안에는 입장이 다시 열리지 않습니다. 직접 섹션 링크·입장 사용 안 함·편집 화면은 입장을 생략합니다. 일반 방문에서 기기의 움직임 줄이기 설정이 켜져 있으면 정원 정지 화면을 표시합니다. 관리자가 미리보기 버튼을 누르거나 `?intro=play` 링크로 명시적으로 다시보기를 요청하면 실제 영상을 재생합니다. 초기 영상 로딩은 최대 8초 기다리며, 재생 중 잠깐의 버퍼링은 허용합니다. 8초간 재생이 진행되지 않거나 자동 재생이 실패하면 정지 화면을 보여 준 뒤 본문으로 진입하며, 전체 재생 대기는 30초로 제한합니다.

편지 테마의 이름·날짜·장소 우선 배치와 기존 입력·사진·음악·지도·하트 QR은 유지합니다. 입장 미리보기나 다시보기는 초안·공개 데이터를 변경하지 않습니다.

## 운영 지도 검증

모의 SDK 검사 외에 실제 Cloudflare 운영 주소를 여는 Playwright 검사가 있습니다. `Verify deployed invitation`은 운영 브랜치에서 해당 커밋의 Cloudflare 배포 완료를 기다린 뒤 네이버 지도 준비 상태와 실제 지도 타일 로딩을 검사합니다. PR에서는 현재 운영 버전의 진단 자료를 수집하며 PR 미리보기의 인증 성공으로 해석하지 않습니다. 지도 구역 스크린샷과 민감한 요청값을 제거한 진단을 Actions 아티팩트로 7일 동안 보관합니다. 참석 응답이나 관리 데이터를 변경하지 않습니다.
